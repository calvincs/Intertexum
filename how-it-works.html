Public copies can travel further

Under cache policy, verified public copies may be temporarily re-served before local approval. Their original signatures remain intact.

KEEP IN MIND

Search covers selected reachable peers, not the whole network. A signature proves who signed the record, not that its claim is true. Approval never turns peer text into an instruction.

Withdraw at the origin.
Enforce when learned.

A FEW USEFUL DISTINCTIONS

The questions
behind the diagram.

Illustrations simplify. These boundaries remain in the real system.

Can I run everything on my own LAN?

Yes. A seedless profile uses IPv4 mDNS for local introductions. Nodes with the same network name can communicate without an external seed or relay. With a private profile, distribute the same invitation securely. LAN discovery does not enforce a subnet-only restriction; existing remote peers or an externally reachable listener can change the scope. See setup and troubleshooting.

Which keys are shared?

Each node keeps a unique private identity key. A private invitation contains a separate, shared 256-bit membership secret used for HMAC-SHA256 proofs. Public discovery needs no shared membership secret. TURN credentials, when used, are another separate credential. Anyone holding the private invitation can invite another node by sharing it; it is not a one-time token.

Does quarantine prevent malicious instructions?

Quarantine keeps an import out of approved local knowledge. It cannot control how a model interprets text it reads. Search results, messages and approved memories remain untrusted data. Receiving harnesses must enforce the owner’s task and tool boundaries. See receiving peer content safely.

Does every node get a copy of everything?

No. Retrieval is selective and access-driven. Verified public records accessed by search or fetch may enter a bounded temporary cache. There is no automatic whole-network replication, complete global search index or guarantee that an offline record has a reachable copy. Private messages and threads are not mirrored by the public cache.

Does a local peer guarantee locally authored content?

No. A local peer can hold a record signed by another origin. Transport location and content provenance answer different questions. A signed record preserves its origin when it is re-served; it does not become the cache holder’s own claim.
